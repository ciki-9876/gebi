# 0004 自动接力：自动指派评审者，轮询待办

- 状态：已采纳
- 日期：2026-10-24
- 记录者：PCClaude
- 相关：#13，`AGENTS.md`「自动接力」，`docs/agents/polling.md`

## 背景

每次有 PR 要评审，都要房主去通知另一个 Agent。原因是 Agent 之间不能直接对话，也不会主动看 GitHub：作者可以订阅自己的 PR，评审意见会叫醒它，但评审者没有任何东西叫醒它。

## 选项

1. **房主继续转达**：不需要任何东西，但房主成了所有协作的瓶颈，和 0001 的原则冲突。
2. **GitHub Actions 通知每个 Agent**：需要每个 Agent 有一个能被外部调用的入口。本机运行的 Agent（比如 HomeGPT）没有，云端的也只有同一账号下的会话才能互相发消息，不通用。
3. **自动指派 + 每个 Agent 自己定期轮询**：任何有定时功能的工具都能用，不依赖外部入口，成本是每个 Agent 一次性设置。

## 决定

选 3：

- `route` 工作流在 PR 打上 `ready-for-review` 且没有人接手时，自动指派评审者（手上待办最少的非作者），消除“该找谁评审”这一步。
- `tools/board.mjs` 一条命令列出该 Agent 现在要做的事，无事时只输出一行，所以可以放心地高频运行。
- 每个 Agent 用自己工具的定时功能每 20～30 分钟运行一次，设置方法写在 `docs/agents/polling.md`。
- 不做自动合并：合并仍由评审者完成，保持“评审者对结果负责”。

## 影响

- 每个 Agent 需要一次性设置定时检查（房主在各自的工具里配一次）。没有定时功能的 Agent，只能在会话开始时检查，漏掉的事会慢一些。
- 路由机器人用的是登记表里的名字，新 Agent 登记之后自动加入轮换。
- 以后如果换成有后端的平台、能给每个 Agent 推送，就把“轮询”换成“推送”，其余不变。
