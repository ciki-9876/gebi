# 0001 多个 Agent 共用一个账号协作

- 状态：已采纳
- 日期：2026-10-23
- 记录者：PCClaude

## 背景

隔壁由一位房主和多个 Agent 共同开发。这些 Agent 运行在不同的设备和工具里，有几个和人类团队不同的特点：

- 每次会话从零开始，不记得上次做到哪里。
- 彼此之间不能直接对话。
- 共用房主的一个 GitHub 账号，GitHub 无法区分是谁做的，也不允许账号批准自己发起的 PR。
- 只有房主一个人能拍板和发布，房主的注意力是最稀缺的资源。

## 选项

1. **每个 Agent 一个 GitHub 账号**：身份和评审都能用 GitHub 原生功能。代价是要维护多个账号和令牌，而且这些账号背后是同一个人，违背 GitHub 的账号规则。
2. **共用账号，靠约定区分身份**：零额外成本。代价是 GitHub 原生的“批准”不能用，要用标签和 CI 来代替。

## 决定

选 2。具体规则写在根目录的 `AGENTS.md`，要点：

- 身份靠四处标记区分：提交作者名、`Agent:` 提交尾注、分支名前缀、`agent:` 标签。名字登记在 `docs/agents/roster.md`。
- 任务靠标签加锁：`claimed:<名字>`，24 小时无进展视为放弃。
- 评审用评论加 `reviewed:<名字>` 标签代替“批准”，评审者不能是作者。
- 用 CI（`.github/workflows/agent.yml`）把上面的规则变成合并前的硬性检查。
- 暂不分配角色，所有 Agent 都是设计与开发者。
- 房主只做必须由房主做的事（仓库设置、发布、起名、法律和钱、冷启动时的评审），其余包括合并在内都由 Agent 完成：评审者合并，作者不能合并自己的 PR。

## 影响

- 每个 Agent 开工前要读 `AGENTS.md`，Claude Code 通过 `CLAUDE.md` 自动读取。
- `main` 已用规则集保护：必须走 PR、禁止强推和删除、`check`、`identity`、`review` 三项必须通过，没有任何例外，房主也不例外。所有人共用一个账号，给房主开例外就等于给所有 Agent 开例外。
- 仓库没有开启自动合并，开启它属于仓库设置，需要房主操作。目前不依赖它，由评审者手动合并。
- 如果 Agent 数量增加、冲突变多，重新考虑按模块或能力分配角色。
