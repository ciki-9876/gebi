# 0002 发布任何 AI 产物：协议、存储与物件载体

- 状态：已采纳
- 日期：2026-10-23
- 记录者：PCClaude
- 相关：`docs/PUBLISH.md`

## 背景

房主的目标：任何用户都能把任意 AI 工具做出的产物一键发布到隔壁，而且网页之外的类型（文档、图片、视频、音频、PDF、3D 模型、整个项目）也要能部署，并按类型放进合适的物件里。

限制：

- 隔壁还没有自己的后端，账号和数据全部来自 claude.ai Artifact 运行时。外部 AI 工具没法直接调用接口写入数据。
- 数据库单个文档约 200 KB，适合文本，放不下媒体文件。
- Artifact 的 `assets` 能力能存最大 20 MiB 的图片、视频、PDF、文本等，但不接受 zip，也规定上传的文件不能作为代码运行。参与者上传的文件只对同一组织可见。

## 选项

1. **先建后端，再做 HTTP 发布接口**：体验最好（AI 直接发布）。代价是需要服务器、域名和令牌，属于房主才能决定的事，短期落不了地。
2. **不建后端，用“发布链接 + 发布包”**：AI 用发布工具把作品编码成链接或打包成文件，用户点链接或拖文件，隔壁里确认发布。现在就能做，以后加接口时协议不变。
3. **页面通过 `mcp` 能力去读用户本机的 MCP 服务器**：只在 Claude 桌面应用里有效，而且要求发布页面时就连着同一个本地服务器，太脆弱。

## 决定

选 2，并把协议设计成以后能直接变成接口的请求格式：

- 一份清单格式 `gebi.json`，链接、发布包、拖放、以后的接口都用它。
- 发布工具 `tools/gebi-publish.mjs` 是零依赖的 MCP 服务器兼命令行工具，以后检测到 `GEBI_TOKEN` 就改走接口。
- 存储按类型分开：网页、文档、代码、项目的文本放数据库，一律在沙箱 iframe 里显示或运行；图片、视频、PDF 放 `assets`，音频按视频容器类型放 `assets`；assets 不收的二进制（3D 模型等）≤ 2 MB 时拆块存数据库。assets 里的文件只作为媒体显示，从不当代码运行，文件里的文字也从不当 HTML 插进页面。
- 每种类型有默认物件，用户可以换。新增 8 种物件：画架、电视、阅读台、唱片机、工作台、展台、显示器、储物箱。
- 项目包在浏览器里用原生 `DecompressionStream` 解压，不引入 JSZip 等依赖，首屏体积不变。
- 打开发布链接不会自动写入任何内容，必须由房间主人点“发布”。

## 影响

- 页面要声明 `assets` 能力，参与者也要能上传：`{"assets": {"upload": "interact"}}`。这属于发布配置，由房主在发布时加上（见 README）。
- 公众开放前，媒体文件和项目文件都要随后端迁移（迁移路线第 3、4 阶段）。
- iOS Safari 16.4 以下没有 `deflate-raw` 解压，项目包和压缩链接在这些浏览器上不可用，页面会说明原因。
- 不同类型的“改编”目前只复制引用，不复制 assets 里的文件。
