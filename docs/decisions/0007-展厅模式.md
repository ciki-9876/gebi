# 0007 展厅模式：把一场线上活动做成一间展厅

- 状态：已采纳（演示阶段）
- 日期：2026-11-10
- 记录者：PCClaude
- 相关：`docs/ARCHITECTURE.md`「展厅模式」

## 背景

房主重新审视了定位：与其做“每人一间常驻房间的作品社区”，不如先做“小社群主理人的线上活动场地”，第一个场景是独立游戏圈子的线上 game jam 展示夜，明确欢迎用 AI 做的作品。房主希望先有一个看得见的 demo。

## 选项

1. **重做一个 demo**：干净，但要把房间、作品窗口、沙箱、SDK 重写一遍，而这些正是展厅需要的。
2. **新开一个仓库，复制代码再删**：两份代码以后各改各的。
3. **在现有代码里加一个模式**：地址带 `?hall` 时走展厅，其余不变。

## 决定

选 3。

- 展厅是一间 `hall: true` 的房间，展位复用街机和展示屏，作品复用作品窗口和 SDK。
- 新代码集中在三个文件（`27-hall-works.js`、`28-hall.js`、`29-hall-social.js`），对原有文件只加了十几处一行的分支（`if (HALL.on) …`）。原来的输入、主循环、启动三个文件顺延为 30、31、32。
- 地球、个人房间、装修、收藏改编、主题周、Bit 在展厅模式下不出现，但代码没有删：等展厅的方向被真实活动验证之后再决定删不删。
- 数据新增两个集合 `hall` 和 `hallp`，仍然是“每人只写自己的文档”。
- 在场用数据库低频同步，不引入实时服务。
- 演示访客和示例反馈只为了一个人预览时展厅不是空的，全部在界面上标注“演示”，可以在活动说明里关掉。

## 没有做的

- 语音、别人正在玩的画面、主理人自己建活动的界面、超过 8 个展位的展厅。
- 自己的后端。组织外的人依然只有查看权限，所以这一版只能演示，不能办真实的公开活动（迁移路线第 3 阶段不变）。
- 反馈的访问控制：现在只是界面上不显示给别人，数据本身可读。

## 影响

- 发布到 claude.ai 时权限规则要加 `hall`、`hallp` 四行（见架构文档）。这属于发布配置。
- 以后改 `17-windows.js`、`16-panels.js` 等文件里带 `HALL.on` 的分支时，两种模式都要走一遍。
