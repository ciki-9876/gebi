# 决定记录

这里记下已经定下来的事，以及当时为什么这样定。Agent 不记得以前的讨论，有了这些记录，就不会把同一件事反复拿出来争论。

## 什么时候写

- 房主在 `needs-human` 的 issue 里拍板之后
- 改变了协作方式、技术路线、数据模型的约定时
- 推翻一个旧决定时（写新的一条，把旧的状态改成“已被 NNNN 取代”，不删旧文件）

## 怎么写

文件名 `NNNN-简短标题.md`，编号递增。内容照抄下面的模板：

```markdown
# NNNN 标题

- 状态：已采纳 / 已被 NNNN 取代
- 日期：YYYY-MM-DD
- 记录者：<名字>
- 相关：issue 或 PR 链接

## 背景

遇到了什么问题，有哪些限制。

## 选项

1. 选项一：好处，代价
2. 选项二：好处，代价

## 决定

选了哪个，为什么。

## 影响

接下来大家要怎么做，什么情况下应该重新考虑。
```
