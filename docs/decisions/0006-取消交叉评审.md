# 0006 取消交叉评审和轮询，Agent 自己验证并合并

- 状态：已采纳
- 日期：2026-10-29
- 记录者：PCClaude
- 相关：#31（暂停开关），取代 0004、0005 和 0001 里评审与合并的部分

## 背景

0001 起，协作规则要求每个 PR 由作者以外的 Agent 评审、评审者合并；0004、0005 为了让评审者及时发现待办，加上了自动指派评审者和各 Agent 的定时轮询。

房主 2026-10-29 判断：**这套做法太贵，决定放弃多 Agent 之间的协作流程**，但仍会让不同的 Agent 分头开发、提交这个项目。成本主要来自三处：

1. **每个 PR 至少多读一遍。** 评审者要把改动、相关代码、规则文档重新读一遍，重档还要自己写测试复现。#12 这个只改了一个函数的修复，来回评审了三轮（两次“需修改”，第三次通过），每一轮评审者都要重新读改动并自己跑测试。
2. **定时轮询每次醒来都要重读上下文。** 只能定时唤醒模型的环境，没有待办也要花一次完整的会话。会话越长，每次醒来越贵：上下文积累到几十万 token 时，每醒一次就要整段重读一遍。
3. **评审的周期受制于最慢的参与者。** #27 在等评审者上卡了两天，期间所有人的轮询都在继续花钱。

## 选项

1. **保持现状**：每个改动都有第二双眼睛，但成本持续最高，而且最慢的参与者决定整体速度。
2. **减轻**：只对改到规则、工具、数据模型的 PR 做评审，轮询降到每天一次。省一部分钱，但仍然要维护一整套机器人和规则，每天仍有固定开销。
3. **取消交叉评审和轮询**：作者自己验证、自己合并，Agent 只在房主启动会话时工作。成本最低、最快，代价是没有人替作者把关。

## 决定

选 3。

- **不再要求评审。** PR 的合并条件只剩 `check`（代码规范）和 `identity`（身份标记）两项 CI 检查，通过后**作者自己合并**。房主已经把仓库规则集里对 `review` 检查的要求去掉（2026-10-29）。
- **自己验证，并写下来。** PR 描述里的“怎么验证”写清楚你跑了什么检查、走了验收清单的哪几条路径。没有别人把关，这一节是房主事后抽查的依据。
- **改动较大的事照样写决定记录**：改数据模型、改设计系统、新增依赖、推翻旧决定。写记录不需要别人批准，但要让别的 Agent 和房主看得懂。
- **不再轮询，不设定时任务。** Agent 只在房主启动会话时工作，做完就结束；没做完的写在 PR 的“交接”里。
- **保留的东西**，因为它们不花钱，又能防止几个 Agent 互相踩脚：身份标记（作者名、`Agent:` 尾注、分支名、`agent:` 标签）、先领 issue 再动手、开工前看有没有打开的 PR 动同一个文件、不直接推 `main`、一律走 PR。
- **移除的东西**：`route` 工作流和 `tools/route-pr.mjs`（自动指派评审者），`tools/board.mjs`、`tools/test-board.mjs`（轮询），`tools/review-now.mjs`，`docs/agents/polling.md`、`review-now.md`、`capabilities.md`，`agent.yml` 里的 `review` 作业，`check-agent.mjs` 里的评审检查。Git 历史里都还在，以后要用可以找回来。
- **没有合并、直接关闭的**：#18（本机唤醒器）、#27（每日红蓝辩论机器人）。#29 是辩论的一次手动试跑，作为记录保留。

## 影响

- **风险要说清楚：没有第二双眼睛。** 作者自己的盲点没人帮着查。缓解办法有四个：CI 的两项检查仍然拦代码规范和身份；PR 是唯一的合并通道，出了问题可以用一个 PR 回退；验证过程写在 PR 里，房主可以抽查；改动大的事有决定记录。
- **每个 Agent 要对自己的改动更小心。** 原来靠评审者发现的问题（漏掉的边界情况、没跑的验收路径、规则文档没同步），现在要作者自己在合并前想到。建议改完用 `git diff origin/main` 把自己的改动再读一遍，再合并。
- **`CODEOWNERS` 里指定的维护者评审不再起作用。** 房主在规则集里没有要求代码所有者评审，那几条（`tokens.css`、`design-system/`、`tools/`、`.github/` 等）现在只是一个提示，没有强制力。
- **不同工具的 Agent 仍能分头干活**，这一点没变：名字、分支、尾注、领取，所有这些都不依赖评审。
- **什么时候重新考虑：** 出现了合并后才发现的、本该被评审拦住的严重问题（例如把线上版本弄坏、数据丢失），或者房主发现需要一个 Agent 只做检查。到时候可以只恢复**对特定目录**的评审（比如数据模型），而不是恢复整套流程。
