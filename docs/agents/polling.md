# 定期检查待办

Agent 不会主动看 GitHub，所以每个 Agent 要设一个**定期检查**。检查本身很便宜：一条命令，没事就什么也不做。

```bash
node tools/board.mjs <你的名字>
```

没有待办时只输出一行“现在没有需要你处理的事”。有待办时按它列的顺序处理：先评审、再修改、再合并，处理完再跑一遍。

PR 一打上 `ready-for-review`，评审者由工作流 `route` 自动指派，不需要作者或房主去通知。

## 设置定时检查

你的工具有什么定时功能，就用什么。频率 20～30 分钟一次，不需要更快。

| 工具 | 怎么设 |
| --- | --- |
| Claude Code（云端会话） | 用定时任务：让 Claude 创建一个每 30 分钟触发的任务（`create_trigger`，cron 例如 `*/30 * * * *`），提示词见下 |
| Claude Code（本机） | `/loop 30m <提示词>`，或者用定时任务 |
| Codex 桌面应用 | 在应用里建一个 Automation（自动化），每 30 分钟运行下面的提示词，工作目录选自己的那份克隆 |
| 其他工具 | 用它自带的计划任务；没有的话，用系统的 cron（macOS / Linux）或任务计划程序（Windows）每 30 分钟运行 `node tools/board.mjs <名字>`，输出里有“待办”时再叫醒 Agent |

没有任何定时功能的 Agent，只能在每次会话开始时跑一遍 board。那样它漏掉的事，由其他 Agent 在 PR 上留言催（`handoff:any` 会让别人也看到），最后才是房主。

## 提示词

把 `<名字>` 换成这个 Agent 的名字：

```
检查隔壁仓库有没有需要你处理的事。

1. 进入你自己的克隆（不要用别人的目录），git fetch origin main。
2. 运行 node tools/board.mjs <名字>。
3. 如果输出“现在没有需要你处理的事”，什么也不做，也不要发任何评论。
4. 否则按输出的顺序处理：
   - “待你评审”：读 AGENTS.md「评审」，按格式发评审评论，通过的话打 reviewed:<名字>。
   - “等你修改”：按评审意见修改，推送，回复每一条，改回 ready-for-review。
   - “可以由你合并”：确认三项检查全绿，再合并。
   - issue：按 AGENTS.md 的任务协议处理。
5. 处理完再运行一遍 board，直到它说没有事了。
遇到只有房主能做的事，按 AGENTS.md 打 needs-human 并说明原因，不要自己拍板。
```

## 注意

- 同一台电脑上的多个 Agent 各用各的克隆，各自设置自己的名字，不要用 `--global`。
- 检查频率不要低于 15 分钟，GitHub 接口有限流。
- 评审和合并都不是“看一眼”的事。board 只告诉你有事，评审要按 AGENTS.md 老老实实读改动、跑检查。
