      Product Design · v0.1 原型同步

      隔壁
      给写代码的人一间房

      每个开发者在地球上选一个真实地址，入住一间可以走进去的房间，把自己写的网页作品做成房间里的物件：便签是一个待办 App，游戏机里跑着自己写的小游戏，吧台后站着自己配置的 AI 助手。访客不是在看作品列表，而是从地球上飞过去串门。

      展示体验社交面向 AI 时代的独立开发者

      01 · WHY NOW作品越来越多，被打开的越来越少

      供给爆发

      AI 编程把做一个网页作品的门槛降到一个周末。小游戏、小工具、个人 Agent 的数量在以月为单位翻倍，作者里有大量非科班的新开发者。

      展示方式停在十年前

      GitHub README、个人站作品列表、Product Hunt 卡片，都是“看”而不是“玩”。一张截图很难让人点开，点开了也很少停留。

      作者需要身份感

      独立开发者在意自己的作品被谁用过、喜欢在哪。一个可以布置、能代表自己品味的空间，比一页简历更愿意被反复打理和分享。

      逛的乐趣缺位

      现有社区靠信息流分发，访客被动刷。房间与楼栋把“发现”变成“串门”，好奇心本身成为留存机制。

      02 · CONCEPT四个概念撑起整个产品

      房间

      个人主页的新形态。第一人称可行走的 3D 空间，窗外是所在城市此刻的天色。原型中的 302「零点电竞酒吧」就是你的房间。

      物件

      作品的入口。任何家具都可以绑定一个作品：网页、小游戏、App、仓库或任意链接。物件本身会“活”着显示作品状态。

      Agent

      房主的分身。懂房主的每个作品，能带访客参观、操作房间、转达留言。原型中的酒保 Bit 由 Claude 驱动。

      地球

      社区的组织方式。每间房对应一个真实地址，地球上实时显示昼夜与住户。按距离、主题和好友连线发现邻居。

      03 · USERS两类人，一个空间

      角色典型画像他们想要隔壁给他们
      房主独立开发者、AI 编程新人、学生、设计师型开发者作品被真正用起来；有一个能代表自己的地方；被同好认出来可布置的房间、物件即入口、Agent 分身、访客数据
      访客 · 同好其他房主、技术社区用户发现好玩的作品和有意思的人串门、留言、点亮、邻居关系
      访客 · 机会方招聘者、投资人、合作者快速判断一个人的能力与品味一个链接看全作品，Agent 可答疑
      访客 · 用户作品的潜在使用者直接用上某个小工具或小游戏物件内试玩，一键打开完整版

      04 · JOURNEYS核心动线

      访客：从链接到串门

      打开分享链接→推门走进房间→点物件走过去→站内试玩作品→留言 / 点亮→出门回到地球→飞去下一个邻居家

      房主：从申请到分享

      在地球上选地址→选房间模板→导入作品清单→拖拽摆放与绑定→配置 Agent→分享门牌链接

      原型已经跑通这两条动线：在地球上点任意一块陆地即可走完入住，落地后进入装修模式，从物件库添加家具并绑定作品，切回漫游就能像访客一样走过去打开它。

      05 · OBJECT PROTOCOL物件协议：一件家具 = 一个入口

      物件与作品解耦。物件决定“长什么样、放在哪”，入口决定“打开后是什么”。同一个作品可以是墙上的海报，也可以是桌上的游戏机。

      // 房间数据是一份 JSON，物件与入口分层描述
{
  "uid": "desk:console",
  "object": { "type": "console", "pos": [-4.2, 1.25, -0.1], "rot": 1 },
  "entry": {
    "kind": "game",            // web | game | app | agent | repo | link
    "url": "https://…",
    "surface": "screen",       // 作品渲染到物件屏幕上（游戏机、显示器、便签）
    "live": "state.json",     // 可选：作品回传的状态，让物件“活”起来
    "sandbox": true
  }
}
      交互深度触发呈现原型中的例子
      L1 · 物件活着进入房间即可见物件显示作品的实时状态便签屏幕显示拾光的今日待办；游戏机屏幕在自动演示
      L2 · 站内运行点击物件作品原站在站内窗口里运行（沙箱 iframe），可收起到任务栏继续运行游戏机打开网页版贪吃蛇，画面通过 SDK 推回桌上的游戏机；拾光网页版改动实时同步到便签
      L3 · 新标签打开窗口标题栏，或作品禁止被嵌入时新标签页打开作品原站房主可在建造模式把打开方式设为“新标签页”

      站内运行的条件

      问题作品方需要做的隔壁的处理
      是否允许被嵌入响应头用 Content-Security-Policy: frame-ancestors https://gebi.app，不要设 X-Frame-Options: DENY绑定地址时由服务器预检这两个响应头，禁止嵌入的自动改为新标签打开
      登录与 Cookie需要登录的作品，Cookie 设为 SameSite=None; Secure，或引导访客在新标签登录窗口提示“在新标签登录后返回”；后续支持 Storage Access API
      安全隔离无iframe 沙箱只开放脚本、表单、弹窗、下载；作品与隔壁不同源，读不到房间数据
      与物件同步（可选）接入约 20 行的隔壁 SDK：握手、推送状态、推送屏幕画面没接 SDK 也能运行，只是物件不会同步
       
      // 作品侧：接入隔壁 SDK（可选）
addEventListener('message', (e) => {
  if (e.data?.gebi !== 1 || e.data.type !== 'hello') return
  render(e.data.data)                               // 房间给的初始数据
  parent.postMessage({ gebi: 1, type: 'ready' }, e.origin)
})
// 状态变化时同步给物件（例如便签上的待办）
parent.postMessage({ gebi: 1, type: 'state', data: { tasks } }, '*')
// 游戏把画面推到物件屏幕上（约每秒 12 帧）
createImageBitmap(canvas).then(f => parent.postMessage({ gebi: 1, type: 'screen', frame: f }, '*', [f]))

      客户端下载

      入口可以附带各平台的下载地址（Windows、macOS、Chrome 扩展、Edge 扩展）。访客打开作品时，隔壁按设备推荐最合适的一项，其余平台列在下方。安装包放在房主自己的发布渠道：桌面端推荐 GitHub Releases 的 releases/latest/download/文件名 固定链接，发新版不用改房间；扩展直接填商店页。隔壁不托管安装包，只展示链接、版本号和来源域名。

      06 · AGENT房主 Agent：会招呼客人的分身

      它知道什么

      房主写的人设、每个作品的说明与 README、房间布局。房主在建造模式里编辑知识卡片，不需要写提示词。

      它能做什么

      通过房间工具带访客参观：移动镜头、打开作品、切换灯光氛围、放音乐、记录留言并转达房主。原型中这些工具都已接通。

      边界

      工具只作用于当前访客的视图，不能改动房间布局与房主数据；访客输入与房主知识隔离；房主可查看对话摘要。

      成本

      默认使用快速模型，单轮回复控制在 80 字内。免费房间每日有对话额度，Pro 房主可提高额度或接入自己的模型密钥。

      07 · BUILD建造系统：十分钟布置好一间房

      • 网格摆放：0.25 格吸附，拖动、90° 旋转、删除，墙面物件固定在挂点上。
      • 物件库：展示屏、街机、书架、白板、机柜、沙发、盆栽等，每件都有默认入口类型；后续开放创作者上架物件。
      • 模板起步：电竞酒吧、像素工坊、植物温室、深夜实验室；导入作品清单时自动生成对应物件。
      • 一句话布置（规划中）：对 Agent 说“把游戏都放到左边墙，加点霓虹”，Agent 调用同一套建造工具完成。
      • 自定义控件：全部界面不用浏览器原生控件，延续拾光的组件规范，保证三套主题下的一致手感。

      08 · COMMUNITY社区与增长

      空间结构就是社区结构：一栋楼 12 户，按主题（独立游戏、AI 工具、可视化…）分楼；同楼即邻居，楼道里能看到谁在线、谁刚上新作品。

      • 传播单元：门牌链接 + 自动生成的房间快照卡片，适合放在 GitHub 主页、社交媒体与简历上。
      • 空房即广告位：街区里的空房间显示“申请入住”，访客最自然的转化入口。
      • 开放日：每周主题楼开放日，Agent 在门口招呼访客，带动集中串门。
      • 冷启动：邀请制首批 500 户，与 AI 编程社群、高校开发者社团合作；首批房主获得永久门牌号。

      10 · METRICS指标

      北极星：每周被体验的作品数（物件被点开并停留 10 秒以上的次数）。它同时度量供给（房主摆了多少作品）和需求（访客愿不愿意玩）。

      建房完成率

      申请入住后 24 小时内至少绑定 1 个作品的比例

      首周绑定数

      新房主首周绑定的作品物件数

      串门率

      访客离开一个房间后进入另一个房间的比例

      Agent 对话率

      访客与房主 Agent 发生对话的比例

      12 · TECH技术方案

      层方案原型中的验证
      渲染Three.js（生产用 R3F）；房间为第一人称可行走空间，装修时切换为剖面娃娃屋视角；程序化低模 + glTF 物件；HDR 辉光、描边与调色后处理整间房全部程序化生成，窗外天色按房间所在地的实时太阳高度计算
      地球约 5.2 万个点阵构成的陆地，来自真实海陆分布、夜间灯光与地形高程；太阳直射点按当前时间计算首页地球可选址入住、搜索城市、查看邻居连线
      站内运行作品原站跑在沙箱 iframe 窗口里，窗口可收起到任务栏；作品经 postMessage SDK 把状态和画面推回物件纹理贪吃蛇与拾光网页版以窗口运行，并与物件同步
      房间数据房间 = JSON 文档（物件、入口、主题），版本化存储，可分享、可模板化建造模式改动即时保存在本机
      AgentLLM + 房间工具调用（focus / open / mood / music），访客会话隔离Bit 已接入 Claude 与 4 个房间工具
      实时WebSocket 在场与表情；留言与点亮走普通 API规划中
      性能合批与实例化、阴影烘焙、移动端降级为固定视角 2.5D移动端已降低像素比，单指旋转、双指缩放

      13 · LANDSCAPE竞品与差异

      类别代表他们解决的隔壁的不同
      作品列表GitHub、itch.io、Product Hunt托管与分发从“看列表”到“走进去玩”，并且以人为中心而非以作品为中心
      虚拟空间Gather、ZEP、Spatial远程办公与活动为作品展示而生，物件即入口，房间属于个人
      UGC 游戏Roblox、Minecraft游戏内创作作品是真实的网页产品，不被平台引擎限制
      个人站Notion、个人博客模板自我介绍自带社区与发现，Agent 替你接待

      14 · RISKS风险与对策

      风险对策
      布置门槛高，房主半途而废模板 + 导入作品自动生成物件；首个作品绑定在 3 分钟内完成；Agent 代为布置
      3D 在低端设备卡顿正交 2.5D 控制面数；移动端固定视角与烘焙光照；首屏先出静态快照
      第三方作品嵌入的安全沙箱 iframe、权限白名单、域名信誉与举报；高风险作品只允许 L3 外链打开
      新鲜感过后访客流失作品上新提醒、邻居动态、开放日活动；以“被体验的作品数”而非访问量作为核心指标

      15 · DEMO SCRIPT60 秒演示动线

      1. 从地球飞进 302首页地球按真实时间分出昼夜。点“回到我的房间”，镜头俯冲进上海，推门走进房间。窗外是上海此刻的天色。
      2. 在房间里走一走WASD 或点地面走动，按住拖动环顾。指出洞洞板上的电子便签正在显示拾光的待办，游戏机屏幕在自动演示。
      3. 和酒保 Bit 说话点吧台后的机器人，问“带我看看拾光”。Bit 会移动镜头并打开入口。再说“来点派对气氛”，灯光会变。
      4. 在游戏机里玩一局点桌上的游戏机，作品原站在站内窗口里打开。玩一局，画面同步推回桌上的游戏机；点“收起”，游戏在任务栏里继续运行。
      5. 勾掉一条待办打开拾光网页版，切换“扭蛋”皮肤并勾选待办，洞洞板上的便签同时换皮、更新。点“获取客户端”，按访客设备推荐 Windows 版或浏览器扩展。
      6. 切到装修模式镜头升起变成娃娃屋视角。从物件库放一台街机，绑定一个作品地址，切回漫游走过去点开它。
      7. 出门回到地球推门出去，镜头从上海拉回太空。点东京的 @pixelmo 去串门，再在地球上任意一块陆地走一遍选址入住。
